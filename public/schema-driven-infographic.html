Constitutional Development

7 principles + P3 discipline + anti-patterns

1

Spec-First, Always

No code changes without corresponding spec updates. Specs are the source of truth.

Example: CLI command requires flow spec first → then implementation
2

Idempotent from Schema

Application is a deterministic function of specifications. Any undocumented behavior is a bug.

Example: Types generated via json-schema-to-ts, never hand-written
3

Bidirectional Traceability

Every flow links to stories; every story links to flows. Validation enforces this in CI.

Example: story.flowIds ↔ flow.implementsStories — both validated
4

Config-Driven Behavior

Business rules live in JSON, not code. Dave can update triage rules without touching Python.

Example: bpp-config.json contains account mappings, skip rules, keyword rules
5

Integration Contract, Not Domain Invention

Reference QBO's entities, don't reinvent them. Define mappings and extensions on top.

Example: External layer uses QBO Account, Purchase, Bill directly
6

Compounding

Feed learnings back into specs and docs on issue closure. Every solved problem makes future problems easier.

Example: COMPOUND-LEARNINGS.md files created after each feature
7

Fail-Closed Security

Security defaults to deny. Unmatched transactions flagged for review, never silently classified.

Example: OAuth scopes explicitly listed; unknown tx types → "needs-review"

When: Pre-commit + CI/CD · 100% coverage

Testing Principles

Test the Contract
Test schemas (the what), not implementation (the how). If the schema is valid, the output is correct.
Fail Fast, Fail Loud
Validation failures block the pipeline immediately. No silent errors, no soft warnings.
Tests as Documentation
E2E tests mirror user stories. Reading tests tells you what the system does.
